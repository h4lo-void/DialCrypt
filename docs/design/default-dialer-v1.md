# DialCrypt as the Default Phone App (v1 Design)

Status: both phases are implemented (section 8). The feature is available only in debug and field-test builds until the on-device checks in section 9 pass. Release builds disable the dial pad, the in-call service, the screening service and the missed-call receiver in the manifest (placeholder `dialerComponentsEnabled`), so the system cannot even offer the app as the phone app. `dialer/` means `app/src/main/java/io/github/h4lovoid/dialcrypt/dialer/`.

## 1. Goals and non-goals

Goals:

- Let the user make DialCrypt the default phone app (`android.app.role.DIALER`) so that DialCrypt draws the in-call screen and no other app shows the full number of a call. Optionally it also takes the call screening role.
- Keep the existing secure call flow (`IncomingCallService` and `CallRegistry`) as the only owner of secure calls. Becoming the phone app must not change how a secure call is screened, offered, answered or relayed.
- Make the change reversible by the user on the phone and from the root manager, and keep emergency calls working through the system phone app.
- Never put a phone number in a notification, a log line or a window title.

Non-goals: video calls, RTT, voicemail, call settings, contact names, and splitting or managing single participants of a conference. DialCrypt requests no contacts permission, so it shows numbers only.

## 2. Getting and giving back the role

**Eligibility.** The role dialog only offers an app that has: an activity for `DIAL` without data, an activity for `DIAL` with a `tel:` URI (both with `category.DEFAULT`), and a service protected by `BIND_INCALL_SERVICE` that handles `android.telecom.InCallService` and carries the `IN_CALL_SERVICE_UI=true` meta-data. The `CALL_BUTTON` action is handled as well. Call screening needs a service with `BIND_SCREENING_SERVICE` that handles `android.telecom.CallScreeningService`.

**Assignment.** Only through the system dialog opened with `RoleManager.createRequestRoleIntent(ROLE_DIALER)` from the settings page of the secure area, after the PIN was entered. The same screen asks for `POST_NOTIFICATIONS`. After the phone role is held, a second row offers "also take over call screening" through `DialerRole.requestScreeningIntent()`. Its text says what is lost: Google's spam call filtering. The module never assigns a role at boot. The settings row reads the state from `RoleManager.isRoleHeld` and stores nothing. Its visibility is the build constant `DIALER_ROLE_UI`: true for debug and field-test builds, false for release builds. Release builds also disable the components the role needs (manifest placeholder `dialerComponentsEnabled` = `false`), so the role cannot be granted by any other route either.

**Launcher entry.** A launcher alias named "Phone" is enabled (with `DONT_KILL_APP`) only while the role is held and disabled otherwise. `SecureActivity` and `DialerInCallService` each synchronize it when they start.

**Giving the role back.** Three paths, all independent of the App being healthy:

1. The settings row opens `Settings.ACTION_MANAGE_DEFAULT_APPS_SETTINGS`.
2. The Action button of the root manager runs `action.sh`, which gives `DIALER` and `CALL_SCREENING` back to the system phone app with `cmd role add-role-holder --user 0 <role> <package>` and prints one line, `dialer=<package>`.
3. Disabling or removing the module removes the package; Android then falls back to the phone app of the system image.

On-site fallback from a root shell: `cmd role add-role-holder --user 0 android.app.role.DIALER com.google.android.dialer`.

## 3. Processes and components

| Process | Components | Role |
|---|---|---|
| `:call` | `IncomingCallService` (UI=false), `DialerInCallService` (UI=true, RINGING=false), `InCallActivity`, `CallActionReceiver`, `CallRegistry`, `CallWatchdog` | Everything that touches a `Call` object. A `Call` can only be used in the process that Telecom bound, so the UI and the services share this process. `DialerInCallService`, `InCallActivity` and `CallActionReceiver` are `directBootAware` (section 8). |
| `:dialer` | `DialpadActivity` (keypad and recent calls), `MissedCallReceiver`, `AllowAllScreeningService` | Keypad, recent calls, missed-call notification, call screening that allows every call. Never touches a `Call`, so a crash here does not affect a call in progress. Of the other packages it reads only `incoming/screen` (the display setting and the contact number index). |
| `:secure` | unchanged | Secure calls, PIN, vault, daemon connection. |

Both in-call services run in `:call`. Each reports its calls to `CallRegistry` together with a source (`CallSource.NON_UI` or `CallSource.DIALER_UI`). On every bind each service refreshes `roleHeld` from `RoleManager.isRoleHeld(ROLE_DIALER)`, and the registry accepts a call only if `accepts(source, roleHeld)` holds: with the role held, only `DIALER_UI`; without it, only `NON_UI`. Whether Telecom also binds the non-UI service while the role is held makes no difference. When the role is given back, behavior is the same as before this feature.

`DialerInCallService` writes call state into `InCallStore` (a list of calls, audio state, the "show full numbers of contacts" setting, the contact index answers for the numbers on a call) which the in-call screen renders. `InCallStore`, the call commands and the `Call` callbacks run on a dedicated `HandlerThread` named `dialer-call`, not on the main thread. Notification actions go through `CallActionReceiver`, which hands the work to that thread with `goAsync()`. Each pending intent carries an id that is valid only inside the running process and a 16-byte random nonce, so every action from before a process restart is ignored.

## 4. Join with the secure flow

- **Single owner.** Every answer goes through `CallRegistry`. With an offer to the secure app, "answer normally" calls `answerPlain(token)`; without one it calls `answerOrdinary(call)`, which returns false when the call is already claimed by the secure flow and records that the call was answered plainly otherwise.
- **Screening in progress.** While screening of an incoming call is still pending, the screen shows a masked number and "checking", the answer button is disabled and the notification offers only decline. The answer button is enabled when screening finishes or after 2 seconds, and the notification is posted again. A call from a secure contact is marked for call log cleanup even if the user answers before screening finishes.
- **While the secure flow owns a call.** `IncomingUiPolicy.mayShowInCall` is checked at four entry points: `onCallAdded`, `onBringToForeground`, the full-screen intent and the notification's content intent. When it says no, `InCallActivity` is not started, the notification has no full-screen intent and no content intent, and a running `InCallActivity` is closed with `finishAndRemoveTask()` when `InCallStore` emits on `finishRequests`. Only a neutral "call in progress" notification with a hang-up action remains. The secure screens are never contested by the in-call screen.
- **Second call during a secure call.** `:call` creates `noBackupFilesDir/secure_call_busy` while a secure call is owned and removes it afterwards and at service start. The keypad asks `DialPolicy.allow(emergency, busy)` with `busy = marker exists && TelecomManager.isInCall()`; only emergency numbers pass while busy, and an exception from `isEmergencyNumber` counts as an emergency number. A call that another app places anyway is disconnected in `onCallAdded`, and a secure call that was put on hold is resumed.
- **Call log.** Telecom writes it as usual. `CallLogEraser` keeps its scope: only entries of secure calls are removed.
- **End and answer, merge.** Both are dialer actions on the active call, so they follow the same rule as hold and swap: while the secure flow owns a call neither is offered (a waiting call can then only be declined, `WaitingCallPlan.choices`) and `TelecomCallCommands` refuses them.

## 5. Notifications and number masking

- Channels: `dialer_incoming_v1` (high, silent, public), `dialer_ongoing_v1` (low), `dialer_missed_v1` (default); notification ids 4201, 4202 and 4203. Telecom plays the ringtone and vibrates and respects Do Not Disturb.
- Title, text, person, ticker and extras never contain a number. The incoming notification uses `CallStyle.forIncomingCall` with a full-screen intent. If the full-screen intent is not allowed, the activity is started directly. Answering starts `InCallActivity` with `PendingIntent.getActivity`; declining goes through `CallActionReceiver`.
- The in-call screen and the incoming prompt show a caller's number by one rule. A number that is not a DialCrypt contact shows in full, also over the lock screen. A contact's number shows only its last four digits; with the "Show full numbers of contacts" setting on (a one-byte file in `noBackupFilesDir` that `:call` and `:dialer` can read, a damaged file counts as off) it shows in full, but only while the screen is unlocked. Hidden, unknown and payphone callers keep their own words, and the digits the user types on the keypad always show in full.
- `:call` and `:dialer` cannot open the vault, so they ask the contact number index `noBackupFilesDir/number_index.bin`, which `:secure` rebuilds whenever the unlocked contacts change. The index is keyed by the ending of a number (`NumberTails`): its last 8 digits after leading zeros are dropped. Every way of writing one number (with the country code, with a trunk 0, as dialed locally) has the same ending, so the answer depends neither on the spelling nor on the SIM country at the time the index was built. Only a number whose national part has fewer than 8 digits needs the SIM country; when it is known, the ending with the country code added to a local number, or taken off an international one, is used as well. For every ending of every contact number the file holds the first 20 bits of an HMAC-SHA256 under the Keystore key `dialcrypt_number_index_v1` (not exportable, no user authentication so the lock screen can use it, StrongBox when present), padded with random tags to a multiple of 64 and sorted, plus a key check value. A number is a contact when any of its endings is in the file. About 95 of the 100 million 8-digit endings share one 20-bit tag, so the file together with the key narrows a tag to about 95 candidate endings and cannot tell real tags from filler; a stranger whose ending or tag collides only shows masked. A missing index while a vault exists, a damaged file, a missing or replaced key, and the time before the first unlock (the file is in credential-encrypted storage) all count as a contact. A number with fewer than 5 digits is never a contact. A local number shorter than 8 digits that is not found while the SIM country is unknown counts as a contact, since it may be stored with its country code; under a SIM of another country such a number is not recognized and shows in full. Without a vault there is no index and every number shows in full. Every vault wipe (reset, duress PIN, no ticket left, interrupted setup) deletes the file and the key. A reader (`ContactNumberIndex.open`) reads the file once, checks the key once and tags each ending once, so a list of numbers costs one file read.
- `InCallActivity` and `DialpadActivity` apply the secure window flags (`FLAG_SECURE`). The in-call screen has no text field.
- `MissedCallReceiver` reads only `EXTRA_NOTIFICATION_COUNT` from the missed-call broadcast. It never reads the number or the two pending-intent extras and logs nothing. The notification says "N missed calls" and opens the recent calls tab of the keypad. A count of zero removes it.
- The keypad passes only the characters 0-9 * # + , ; to Telecom and does not judge whether a number is valid.

## 6. Watchdog

A stuck main thread in `:call` would leave a ringing or active call without any control, and Telecom does not hand the call to another app. `CallWatchdog(isCallLive, timeoutMs = 6000, kill)` runs on a background thread and posts a heartbeat to the main looper every second. If a call is ringing, dialing or active, no debugger is attached and the heartbeat is more than `timeoutMs` late, it ends the `:call` process. Telecom binds the service again and `onCallAdded` posts the notifications and the screen again. On start, `DialerInCallService` first runs `CallAudioMuter.recoverLeftover` and `recoverOrphan`, like `IncomingCallService`. `TelecomManager.endCall()` is not used: it ends the foreground call only and is deprecated.

## 7. Emergency calls

- The keypad never blocks a number and does not require the PIN, an accessibility check or hardening for any number. The system emergency button on the lock screen keeps using `ACTION_DIAL_EMERGENCY`.
- For an emergency call Telecom shows the in-call screen of the system phone app. DialCrypt only removes its own notifications and screen when it is unbound and does not take the foreground.
- Level 2 hardening always exempts the system phone app, whoever holds the role, because `pm suspend` would block the screen of that app. The daemon's pre-check reads the package from `cmd telecom get-system-dialer` and falls back to `com.google.android.dialer` when the output cannot be read. If DialCrypt holds the dialer role and the system phone app is not on the system image, the pre-check fails with code 123 (`SystemDialerMissing`). A role holder other than DialCrypt must be on the system image, as before; DialCrypt itself passes because it is installed under `/system/priv-app`.

## 8. Scope of the phases

**First phase:**

- Role request and give-back, launcher alias, settings rows (phone role and call screening role).
- Incoming and outgoing calls, answer, decline, hang up, mute, audio route, DTMF, hold and resume, post-dial pauses and waits.
- Dual SIM: when the phone is set to "ask every time", the call waits in `STATE_SELECT_PHONE_ACCOUNT`, so the screen lists the accounts and calls `phoneAccountSelected`.
- A second incoming call: "hold and answer" (Telecom holds the first call), decline, and swap, which resumes the held call. Other calls are not listed; conference children are hidden.
- Missed-call notification, keypad, call screening that allows every call without reading the number.
- Proximity screen-off while a call is dialing or active, the route is the earpiece and the secure flow does not own the call.

**Second phase:**

- **Recent calls.** A second tab of `DialpadActivity` in `:dialer` (`RecentCallLog`, `RecentCallsModel`, `RecentsScreen`). It reads `_id`, number, type, presentation, date and duration from `CallLog.Calls`, newest first and at most 300 rows; no cached name is read. Incoming and answered-elsewhere rows show as incoming, outgoing as outgoing, missed, rejected and blocked as missed; voicemail rows are not listed. Each row shows the direction, the number by the rule of section 5 with the screen counted as unlocked (the keypad never shows over the lock screen), the time (time of day for today, else the date) and, for connected calls, the duration. Tapping a row with a number dials it through `Dialer.dial`, the keypad's path, so the emergency and secure-call checks apply; hidden, unknown and payphone rows cannot be tapped. One row is deleted by `_id`; "Clear all" deletes every row after a confirmation. Deleting runs on its own thread and does not wait for a refresh; a refresh that a delete overtook loads again. `READ_CALL_LOG` and `WRITE_CALL_LOG` were already declared; the dialer role grants them, and the Magisk module grants them at every boot. The missed-call notification opens this tab.
- **Rows of secure calls in the recent calls.** `CallLogEraser` needs up to 30 s to find and delete the entry of a secure call, so the list does not rely on timing. As soon as `CallRegistry` marks a call for erasing, `:call` adds a line with the call's start time (no number) to `noBackupFilesDir/call_log_erase_pending` (`PendingLogErase`) and removes it when the eraser has deleted the entry or given up. While a line exists, every refresh of the list, the one in `onStart` included, leaves out all rows dated from 5 s before that start on; the marker is read before and after the call log, since it is written before the entry appears and removed after the entry is deleted. While rows are held back the screen looks once a second whether the marker changed and then loads again. A marker nobody looks after is dropped: by readers when `:call` is not running or the file was last written more than 6 hours ago, and by `:call` when one of its services starts with nothing pending. Nothing is read or written before the first unlock.
- **End and answer.** A call waiting next to an active or dialing call offers "Hold and answer", "End current call and answer" and "Decline". `WaitingCallPlan.steps` disconnects every current call (up, not held, not ringing, not ending, not a conference child) and then answers the waiting call through `CallRegistry`, like the other answer; a held call stays held. The button waits for screening like the answer button.
- **Merge.** With exactly one active and one held call, and `CAPABILITY_MERGE_CONFERENCE` or conferenceable calls on either, the screen shows "Merge calls" (`MergePolicy`). The command uses `mergeConference()` when the active call has the capability, otherwise `conference()` with the held call. The conference parent (`PROPERTY_CONFERENCE`) shows as "Conference call" with the number of its children when the network lists them; the children stay hidden, and hanging up disconnects the parent, which ends the whole conference. Splitting and managing single participants are not offered.
- **Direct boot.** `DialerInCallService`, `InCallActivity` and `CallActionReceiver` are `directBootAware`, so Telecom binds DialCrypt also before the first unlock after boot. The app has no `Application` class and no content provider in `:call`, and nothing in `:call` uses `SharedPreferences`. Every file it reads is behind `DirectBoot.isUserUnlocked` (`UserManager.isUserUnlocked`): `DisplaySettings` reads as off, `ContactNumberIndex` answers unknown, `SecureBusyMarker` is neither read nor written, `CallAudioMuter` postpones its leftover check, and `CallRegistry` screens with mode OFF, so no secure offer is made. Every shown number then has only its last four digits visible, strangers included, because the index cannot be read. `IncomingCallService`, the prompt and `:secure` stay credential-bound. The resets that `DialerInCallService` skips before the first unlock (the leftover call mute of `CallAudioMuter`, a stale `secure_call_busy`, a stale erase marker) run once right after `ACTION_USER_UNLOCKED` (`AfterFirstUnlock`, a receiver of the process, so they also run when the call ended before the unlock); the in-call screen then reads the setting and asks the index again about the numbers on a call.

## 9. Checks that need a device

1. `dumpsys telecom` shows which in-call services are bound while the role is held. Whether the non-UI service is bound does not matter for correctness; `CallRegistry` accepts only the UI service's calls.
2. The system phone app shows no screen and posts no notification for incoming, outgoing, missed and waiting calls, including its call-screening role.
3. Kill `:call` with `kill -9` while ringing and during a call: the call must continue. Telecom rebinding DialCrypt and Telecom switching to the system phone app are both acceptable; record which one happens.
4. Emergency numbers through the test mode of the telephony emergency number list: dial from the keypad, the system screen takes over, the lock screen emergency button works, and level 2 hardening runs, also with a keypad call after the home button during a secure call.
5. Full-screen intent allowed and denied, and proximity screen-off.
6. Audio route, mute, DTMF, hold, call waiting, dual SIM selection and post-dial characters.
7. Secure incoming call handoff, the secure screens are not covered, a secure outgoing call does not open the in-call screen, a second call from another app is disconnected, and the call log is cleaned.
8. All three give-back paths work, and the level 2 pre-check passes while DialCrypt holds the role.
9. The format of `cmd telecom get-system-dialer` output.
10. A call before the first unlock after boot: DialCrypt draws the screen, the number shows only its last four digits, answer, decline and hang up work, nothing crashes in `:call` (logcat), and after unlocking during the call the screen keeps working. Also check whether Telecom still binds the system phone app or `IncomingCallService`, and that `RoleManager.isRoleHeld` answers before the first unlock. After the unlock a `secure_call_busy` file left by an interrupted secure call is gone and a leftover call mute is restored.
11. Recent calls: the rows match the system call log, delete and clear all remove them there too, a secure call's row never shows, the missed-call notification opens the tab, and calling back a row goes out (and is blocked during a secure call). The secure call's row also stays hidden when the list is opened right after the call and when the eraser needs its full 30 s, and rows held back with it appear once the eraser is done.
12. "End current call and answer" on call waiting, and merging with carriers that offer conference calls (IMS `mergeConference` and `conference`): the participant count, and that hanging up ends every leg.

## 10. Known risks

- Two in-call services of one package may interfere. Mitigation: `CallRegistry` takes calls from the non-UI service when the role is not held and from the UI service when it is held, and every answer goes through it.
- `:call` may crash or hang. A crash makes Telecom rebind; a hang is handled by the watchdog after about six seconds, during which the call cannot be controlled from the app. The secure relay does not survive a restart of `:call`.
- The behavior of the platform can differ from the documented one, for example in emergency takeover, the missed-call broadcast, full-screen intent permission and the time before the first unlock. Mitigation: notifications stay public without numbers, the screen starts directly when the full-screen intent is refused, the system phone app is never disabled, and the release build disables the dialer components until the checks in section 9 pass.
- Direct boot depends on platform behavior that only a device shows (step 10). If anything in `:call` still touches credential-encrypted storage before the first unlock, that process crashes and Telecom falls back to the system phone app. Mitigation: every file access in `:call` either checks `DirectBoot.isUserUnlocked` or already tolerates a missing file, and the release build keeps these components disabled.
- Before the first unlock every number is masked, strangers included: the contact index cannot be read then.
- The erase marker holds back every row from the secure call's start on, also rows of other calls, until the eraser is done (at most about 30 s after the call). If the eraser gives up, has no permission, or `:call` dies, the marker goes and the entry shows like any other; the eraser stays best effort. While a secure call lasts and during the erase, the call's start time is on disk in the app's private storage. A secure call longer than 6 hours loses the marker.
- The index answers by the last 8 digits: two different numbers with the same ending cannot be told apart, so a stranger with a contact's ending shows masked.
- Merging depends on the carrier; some networks do not list the participants, and the screen then shows no count.
- Taking the call screening role removes Google's spam filtering for incoming calls.
- The role dialog and the system "Default apps" page show the disguised app name.
